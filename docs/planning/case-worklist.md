# Hermes Agent 실제 사례 장 워크리스트

작성일: 2026-04-30
정리 상태: 2026-04-30 기준 11장 확장 반영 후 보관

## 목표

11장은 Hermes Agent의 차별점인 `역할형 에이전트 / 기억 계층 / Skill / cron / Slack / GitHub / WikiDocs 검증`을 실제 업무 자동화 사례로 보여주는 장이다.

사례는 기능 나열이 아니라 다음 질문에 답해야 한다.

- 어떤 반복 업무에서 시작했나?
- 하비/방울이/뽀동이/비벙이/하망이/봉구가 각각 무엇을 맡았나?
- 처음에 어디서 막혔나?
- 그 시행착오가 어떤 운영 규칙으로 바뀌었나?
- 독자는 어떻게 따라 하면 되나?

## 현재 11장 구성

현재 11장은 다음 사례를 포함한다.

1. 하망이와 WikiDocs 이미지를 만든 실제 운영 케이스
2. 크론 조사에서 WikiDocs 발행까지 이어지는 AI 업무 자동화 케이스
3. 방울이 확장조사와 뽀동이 글쓰기는 어떻게 이어질까
4. GitHub와 WikiDocs로 콘텐츠를 발행하고 고치는 흐름
5. Slack 스레드에서 하비가 일을 분배하는 방식
6. SEO/GEO 치트시트를 콘텐츠 자산으로 만든 실제 케이스
7. 반복 문서 제작은 AI 에이전트로 어떻게 줄일까
8. 메일 정리와 답장 초안은 AI 개인비서에게 어떻게 맡길까
9. 자료조사 결과를 비교표와 결정 메모로 바꾸는 흐름
10. 매일 아침 브리핑과 주간 리포트는 어떻게 자동화할까
11. 비벙이는 아이디어를 제품 요구사항으로 어떻게 바꿀까
12. 봉구는 실행/배포/검증을 어떻게 이어받을까
13. 파일과 노트는 AI 팀의 장기 기억으로 어떻게 남길까
14. 회의록은 보고서와 발표자료로 어떻게 바꿀까
15. 이미지 생성은 어떻게 요청/검수/재사용 흐름으로 만들까
16. Google Workspace와 메일 MCP는 업무 흐름에 어떻게 붙일까
17. Slack 고객응대는 어떻게 초안/승인/기록 흐름으로 만들까
18. 블로그와 뉴스레터는 어떻게 하나의 원본에서 재가공할까
19. 정기 리서치는 의사결정 회의자료로 어떻게 바꿀까
20. 크론 오류를 Skill/메모리 개선으로 바꾸는 운영 케이스

## 각 사례 공통 점검표

새 사례를 추가하거나 기존 사례를 보강할 때 아래를 확인한다.

- 시작점이 구체적인가: 요청/cron/자료 변화가 보이는가
- 역할 분리가 보이는가: 하비/방울이/뽀동이/하망이/봉구/비벙이 중 누가 무엇을 맡는가
- 중간 판단이 있는가: 보류/확장/발행/승인 기준이 있는가
- 검증이 있는가: 링크/이미지/형식/문체/공개 반영을 확인하는가
- 자산화가 있는가: Skill, 체크리스트, 문서, 다음 사례로 남는가
- 공개 안전성이 있는가: 보호해야 할 정보와 독자에게 필요한 정보가 분리되는가

## 앞으로의 우선순위

사례 수는 이미 충분히 넓어졌다. 다음 보강은 새 페이지 추가보다 대표 사례의 완성도를 높이는 쪽이 좋다.

우선순위:

1. 이메일 자동화: Before/After, 승인 기준, 답장 초안 샘플 강화
2. 이미지/상세페이지: 요청문, 검수 기준, 재사용 파일명 규칙 강화
3. 자료조사/결정 메모: 비교표 샘플, 결정 메모 샘플 강화
4. Slack 역할 분배: 실제 요청문/역할 라우팅 예시 강화
5. WikiDocs/블로그 발행: GitHub 원본과 공개 페이지 검증 차이 강화

## 보관 기준
