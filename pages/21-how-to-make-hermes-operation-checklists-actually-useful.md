## Hermes Agent 운영 체크리스트는 어떻게 써야 할까

![운영 체크리스트를 짧고 실행 가능하게 쓰는 흐름](../assets/how-image-agent-creates-wikidocs-visuals/ch08-3-useful-ops-checklists-codex.png)

[Hermes Agent](https://wikidocs.net/346055) 운영 체크리스트는 긴 문서가 아니다. AI 개인비서, 역할형 에이전트, MCP, cron, WikiDocs 발행처럼 여러 요소가 얽힐 때 먼저 확인할 순서를 짧게 고정하는 도구다.

체크리스트가 실제로 도움이 되려면 설명보다 행동이 보여야 한다. “메모리를 확인한다”보다 “[session](https://wikidocs.net/346126) 내용인지 memory 저장 대상인지 나눈다”가 낫고, “발행을 확인한다”보다 “TOC 링크, 이미지 경로, H1 사용 여부, 본문 raw `.md` 링크를 검사한다”가 낫다.

## 왜 체크리스트는 많은데도 잘 안 쓰일까

잘 안 쓰이는 체크리스트는 보통 세 가지 문제가 있다.

- 너무 길어서 시작점이 보이지 않는다.
- 설명은 많은데 실제 확인 항목이 없다.
- 누가, 언제, 어떤 도구로 확인할지 빠져 있다.

Hermes Agent 운영에서는 이 문제가 더 크게 드러난다. 하비가 메인 창구인지, 방울이에게 조사시킬지, 뽀동이가 문서화할지, 봉구가 실행 검증할지에 따라 체크리스트의 모양도 달라진다.

## 좋은 체크리스트의 조건

| 조건 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 짧다 | 관련 문서를 모두 읽는다 | source of truth 문서 1개를 먼저 본다 |
| 행동이 있다 | 링크를 점검한다 | TOC 링크 missing count가 0인지 본다 |
| 담당이 있다 | 누군가 검수한다 | 뽀동이가 본문, 실행형이 명령 결과를 검증한다 |
| 성공 기준이 있다 | 문제 없으면 완료 | H1 0, 이미지 누락 0, raw `.md` 링크 0 |
| 후속이 있다 | 끝 | 실패 항목은 FAQ 또는 복구 플레이북으로 보낸다 |

## 실제 운영 체크리스트 예시

WikiDocs 장 리라이트 작업의 체크리스트는 이렇게 짧아야 한다.

```text
1. git status가 깨끗한지 확인한다.
2. TOC에서 대상 장의 페이지를 추출한다.
3. 세션 기록, 협업 기록, 팀 공통 기억, 원본 자료 목록에서 실제 운영 근거를 찾는다.
4. 보호해야 할 정보와 불필요한 내부값을 제거하고 상황/판단/기준만 남긴다.
5. 본문 링크는 WikiDocs page ID URL로 유지한다.
6. H1, 헤딩 간격, 이미지 경로, raw .md 링크, 중점 문자, 보호 정보 패턴을 검사한다.
7. 통과하면 변경 이력과 공개 반영 상태를 확인한다.
```

이 정도면 긴 세션에서도 작업자가 길을 잃지 않는다. 더 자세한 설명은 본문에 남기고, 체크리스트에는 실행 순서만 둔다.

## 체크리스트의 위치

체크리스트는 세 곳으로 나뉜다.

| 위치 | 용도 |
|---|---|
| skill | 반복 절차가 도구 사용과 함께 재사용될 때 |
| shared-memory | 팀 공통 규칙과 handoff 기준일 때 |
| WikiDocs | 함께 공유할 운영 기준일 때 |

memory에는 장기 선호와 안정적인 사실만 남긴다. 작업 진행 상황이나 임시 로그는 memory가 아니라 session/search, GitHub, shared-memory에서 회수하는 편이 좋다. 이 기준은 [AI 에이전트 기억 시스템](https://wikidocs.net/345902)와 직접 연결된다.

## 운영 기준

- 체크리스트는 3~9개 항목으로 시작한다.
- 각 항목은 동사로 끝낸다.
- 성공 기준을 수치나 상태로 쓴다.
- 역할이 필요한 경우 담당 에이전트를 적는다.
- 반복되면 skill로 승격하고, 장애 순서가 필요하면 복구 플레이북으로 승격한다.

## FAQ

### 체크리스트는 어디에 두는 게 좋나요?

팀 공통 규칙이면 shared-memory, 반복 절차면 skill, 함께 공유할 운영 기준이면 WikiDocs에 둔다. 같은 내용을 세 곳에 복붙하지 말고 원본 위치를 정해 연결한다.

### 체크리스트가 너무 짧으면 빠뜨리지 않나요?

짧은 체크리스트는 모든 배경을 담지 않는다. 대신 작업 중 반드시 놓치면 안 되는 순서를 고정한다. 자세한 설명은 관련 문서로 연결하면 된다.
