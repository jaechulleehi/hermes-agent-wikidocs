## 매일 아침 브리핑과 주간 리포트는 어떻게 자동화할까

cron 자동화는 “정해진 시간에 실행한다”로 끝나지 않는다. Hermes Agent에서 cron은 새 세션으로 시작되므로, 무엇을 조사하고 어디로 보내고 변화가 없을 때 어떻게 할지까지 prompt 안에 들어 있어야 한다.

이 사례는 매일 아침 브리핑이나 주간 리포트를 자동화할 때 필요한 운영 기준을 정리한다. 핵심은 더 자주 알림을 보내는 것이 아니라, 판단 가능한 신호만 짧게 전달하는 것이다.

## 시작 상황

매일 확인하는 일이 있다.

- AI 뉴스와 제품 업데이트
- 경쟁사 또는 관심 서비스 변화
- 가격/채용/릴리즈 페이지 변경
- 고객 문의나 메일 요약
- 이번 주 콘텐츠 발행 후보

사람이 매번 직접 확인하면 놓치기 쉽고, AI가 매번 길게 보고하면 읽지 않게 된다. 그래서 브리핑 자동화는 `수집`보다 `보고 조건`이 더 중요하다.

## 맡긴 역할

| 역할 | 담당 |
|---|---|
| cron | 정해진 시간에 새 세션으로 작업을 시작한다 |
| 하비 | 변화가 보고할 가치가 있는지 판단한다 |
| 방울이 | 필요한 웹/문서/뉴스 신호를 수집한다 |
| 뽀동이 | Slack에서 바로 읽을 수 있게 짧은 보고로 정리한다 |
| 봉구 | 스크립트/검증/배포 상태를 점검한다 |

## 막힌 지점

cron 작업이 실패하는 이유는 대개 세 가지다.

1. prompt가 현재 대화 맥락에 의존한다.
2. 결과를 어디로 보낼지 명확하지 않다.
3. 변화가 없어도 매번 긴 보고를 보낸다.

cron은 사람이 옆에 있는 대화가 아니다. 실행될 때마다 새 세션으로 시작하므로, 필요한 맥락과 출력 형식이 prompt 안에 있어야 한다.

## 운영 규칙

1. cron prompt는 self-contained하게 쓴다.
2. 조사 범위와 제외 범위를 같이 적는다.
3. 변화가 없을 때는 `[SILENT]` 또는 짧은 무변화 보고 규칙을 둔다.
4. Slack/메일/파일 저장 등 delivery target을 명시한다.
5. 모델 사용량이나 비용이 중요한 작업은 보고에 사용량 확인 항목을 넣는다.

## cron prompt 예시

```text
매일 오전 8시에 실행되는 AI 업무 자동화 브리핑이다.

목표:
- Hermes Agent, OpenClaw, AI Agent, MCP, 업무 자동화 관련 주요 업데이트를 확인한다.
- 새롭거나 실행 가치가 있는 변화만 보고한다.

조사 범위:
- 공식 블로그/릴리즈 노트/GitHub/신뢰 가능한 뉴스
- 단순 홍보성 글이나 중복 뉴스는 제외

출력 형식:
완료: 확인한 범위
핵심: 새로 볼 만한 변화 3개 이하
다음: 하비가 판단해야 할 액션

보고할 변화가 없으면 `[SILENT]`만 출력한다.
```

## 주간 리포트 예시

```text
이번 주 수집된 AI 업무 자동화 신호를 주간 리포트로 정리해줘.

분류:
1. 바로 실험할 것
2. WikiDocs 사례로 남길 것
3. 제품/기능 기획으로 넘길 것
4. 보류할 것

각 항목에는 근거 링크, 왜 중요한지, 다음 액션을 붙여줘.
장황한 배경 설명보다 판단 기준을 우선해줘.
```

## 좋은 예와 나쁜 예

| 구분 | 예시 |
|---|---|
| 나쁜 예 | “오늘 AI 뉴스 20개입니다” |
| 좋은 예 | “새로 실험할 가치가 있는 변화 2개, WikiDocs 사례 후보 1개, 보류 3개입니다” |

## 체크리스트

- cron prompt만 읽어도 작업 목적을 알 수 있는가?
- 조사 범위와 제외 범위가 있는가?
- 결과 전달 채널이 정해져 있는가?
- 변화가 없을 때 조용히 지나갈 규칙이 있는가?
- 다음 액션이 하비/방울이/뽀동이/봉구 중 누구에게 갈지 보이는가?

## 확장 아이디어

모닝 브리핑이 안정되면 가격 모니터링, 경쟁사 업데이트, 콘텐츠 후보 수집, GitHub 릴리즈 감시로 확장할 수 있다. 다만 모든 신호를 자동 발행으로 연결하면 안 된다. cron은 판단의 시작점이고, 발행은 하비의 검토와 뽀동이의 정리, 필요하면 방울이의 추가 조사 뒤에 진행하는 것이 안전하다.
