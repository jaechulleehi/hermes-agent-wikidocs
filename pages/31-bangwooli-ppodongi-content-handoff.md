## 방울이 확장조사와 뽀동이 글쓰기는 어떻게 이어질까

조사형 에이전트와 정리형 에이전트는 같이 움직일 때 강해진다. 방울이가 넓게 근거를 모으고, 뽀동이가 그 재료를 독자가 읽을 수 있는 구조로 바꿀 때 콘텐츠 품질이 올라간다.

문제는 handoff다. 방울이가 좋은 조사를 해도 뽀동이에게 넘기는 형식이 흐리면 글은 다시 약해진다. 반대로 뽀동이가 아무리 구조를 잘 잡아도 원자료가 빈약하면 그럴듯하지만 설득력이 약한 글이 된다.

## 실제 업무 상황

로이드가 “이 주제 WikiDocs에 올릴 만하지 않아?”라고 판단하면, 하비는 먼저 이 주제가 어느 장에 들어갈지 본다. 이후 방울이에게 확장조사를 맡기고, 뽀동이에게는 글 구조와 발행 기준을 맡긴다.

```text
하비: 주제와 발행 의도 판단
방울이: 근거, 사례, 반례, 관련 공식 문서 조사
하비: 조사 결과에서 쓸 재료 선별
뽀동이: WikiDocs 페이지 구조, 제목, CTA, FAQ 정리
하비: 최종 리뷰와 발행 판단
```

## 좋은 handoff에 들어갈 것

방울이의 조사 결과는 길기만 하면 안 된다. 뽀동이가 바로 글로 바꿀 수 있게 다음 정보가 분리되어 있어야 한다.

| 항목 | 필요한 이유 |
|---|---|
| 핵심 주장 | 글의 첫 답변이 흔들리지 않게 한다 |
| 근거 목록 | 주장과 사실을 분리한다 |
| 반례/주의점 | 성공담처럼 보이지 않게 한다 |
| 공식 문서 연결 | 기능 기준과 우리 운영 경험을 구분한다 |
| 실제 운영 장면 | 추상 설명을 케이스로 바꾼다 |
| 민감정보 제거 메모 | 공개 글로 바꿀 때 위험한 내용을 걸러낸다 |
| 추천 배치 장 | TOC 안에서 길을 잃지 않게 한다 |

## 뽀동이가 이어받을 때 보는 기준

뽀동이는 조사 결과를 그대로 예쁘게 다듬는 역할이 아니다. 먼저 독자 문제와 책 안의 위치를 확인한다.

- 이 글은 어떤 독자 질문에 답하는가?
- 기존 장 중 어디에 들어가야 자연스러운가?
- 새 장이 필요할 만큼 같은 유형의 케이스가 반복되는가?
- 첫 문단에서 결론이 보이는가?
- 사례가 공개 가능한 수준으로 정리되었는가?
- FAQ와 체크리스트로 바꿀 수 있는가?

## 나쁜 handoff 예시

```text
이거 조사했어. 대충 콘텐츠 자동화 얘기야. 글로 써줘.
```

이렇게 넘기면 정리형 에이전트는 빈칸을 추측으로 메우기 쉽다. 결과적으로 문장은 자연스러워도 근거가 약해진다.

## 좋은 handoff 예시

```text
주제: cron 조사에서 WikiDocs 발행까지 이어지는 콘텐츠 자동화 케이스
목적: 10장 실제 운영 케이스의 사례로 사용
독자: Hermes Agent로 AI 개인비서와 역할형 에이전트를 운영하려는 실무자
핵심 주장: cron은 최종 글쓰기보다 자동 시작점으로 쓰는 편이 안전하다
원자료: Daily Briefing Bot 공식 가이드, 실제 Slack 운영 흐름, GitHub/WikiDocs 발행 기준
주의점: 내부 링크, 채널 ID, 토큰, 개인 경로는 제거
필수 포함: 역할 분리표, 발행 기준, 재사용 체크리스트, FAQ
```

## 재사용 체크리스트

- 조사 결과에 출처와 날짜가 있는가?
- 근거와 해석이 분리되어 있는가?
- 뽀동이가 추측하지 않아도 될 만큼 목적과 독자가 명확한가?
- 책의 어느 장/페이지에 들어갈지 정해져 있는가?
- 공개하면 안 되는 정보가 표시되어 있는가?
- 최종 글이 체크리스트나 FAQ로 끝나는가?
