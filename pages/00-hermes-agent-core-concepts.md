## Hermes Agent 주요 개념과 기능은 어떻게 연결될까

Hermes Agent를 처음 보면 기능 이름이 먼저 눈에 들어온다. memory, profile, skill, cron, MCP, gateway처럼 낯선 단어가 많다. 하지만 기능을 하나씩 외우는 방식으로 접근하면 금방 복잡해진다.

이 페이지는 책 전체에서 반복해서 나오는 주요 개념을 한 번에 연결하는 안내판이다. 핵심은 단순하다. Hermes Agent는 대화만 하는 도구가 아니라, 요청을 받고, 역할을 나누고, 도구를 연결하고, 결과를 기록으로 남기는 운영 흐름이다.

## 기능보다 흐름이 먼저다

Hermes Agent의 기능은 따로 떨어져 있지 않다. 실제 업무에서는 하나의 요청 안에서 여러 기능이 함께 움직인다.

예를 들어 매일 아침 정보를 모아 요약해 보내는 자동화를 생각해보자. cron이 정해진 시간에 작업을 시작하고, 필요한 도구가 정보를 가져오고, AI가 요약하고, 메시징 채널로 전달한다. 같은 작업이 반복되면 skill이나 체크리스트로 남길 기준이 생긴다. 결과가 콘텐츠가 되면 WikiDocs나 블로그로 이어질 수도 있다.

따라서 기능을 배울 때는 “이 기능이 무엇인가”보다 “어떤 흐름에서 필요한가”를 먼저 봐야 한다.

## 실제 케이스로 보면 이렇게 이어진다

공개 글 하나를 만든다고 해도 흐름은 단순하지 않다.

1. AI 개인비서가 요청을 받는다.
2. 조사형 에이전트가 근거와 맥락을 넓힌다.
3. 정리형 에이전트가 독자 문제와 글 구조를 잡는다.
4. 이미지형 에이전트가 설명 이미지가 필요한 지점을 찾는다.
5. 실행형 에이전트가 파일 수정과 검증을 맡는다.
6. 결과는 WikiDocs, 블로그, 강의, 체크리스트 중 알맞은 형태로 남는다.

이 흐름에서 중요한 것은 모든 세부 정보를 공개하는 것이 아니다. 독자에게 필요한 것은 “무슨 문제가 있었고, 어떤 기준으로 역할과 도구를 나눴는가”다. 내부 설정값이나 사적인 맥락은 빼고, 재사용 가능한 판단 기준만 남겨야 한다.

## 내부 이름은 운영 예시다

하비/방울이/뽀동이/봉구/비벙이/하망이는 책 전체에서 자주 나오는 운영 예시 이름이다. 하지만 독자는 먼저 공개 개념을 이해하면 된다.

- 하비는 AI 개인비서 메인 창구의 예시다.
- 방울이는 조사형 에이전트의 예시다.
- 뽀동이는 정리형 에이전트의 예시다.
- 봉구는 실행형 에이전트의 예시다.
- 비벙이는 제품/기능 정리형 에이전트의 예시다.
- 하망이는 이미지형 에이전트의 예시다.

이름은 귀엽게 보일 수 있지만, 목적은 역할을 짧게 부르기 위한 것이다. “방울이 시켜서 확장조사”, “뽀동이가 WikiDocs 구조 정리”, “하망이가 이미지 제작 방향 정리”처럼 요청이 짧아져도 기대 역할은 분명해진다.

## 이 페이지를 어떻게 쓰면 좋을까

책을 읽다가 기능 이름이 헷갈리면 이 페이지로 돌아오면 된다. 특히 다음 질문을 기준으로 보면 좋다.

- 요청의 입구가 필요한가? → AI 개인비서
- 일이 조사/정리/실행으로 섞여 있는가? → 역할형 에이전트
- 반복 절차를 남겨야 하는가? → skill 또는 체크리스트
- 정해진 시간에 시작해야 하는가? → cron
- 외부 도구와 연결해야 하는가? → MCP 또는 gateway
- 결과를 독자용 지식으로 남겨야 하는가? → WikiDocs 또는 콘텐츠 시스템
