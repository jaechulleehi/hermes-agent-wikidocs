## Slack 고객응대는 어떻게 초안/승인/기록 흐름으로 만들까

Slack 고객응대 자동화는 속도를 높일 수 있지만, 자동 답변으로 바로 보내면 위험하다. 고객에게 나가는 말은 회사의 약속이 되기 때문이다. Hermes Agent로 Slack 고객응대를 다룰 때 핵심은 `문의 수집 → 맥락 확인 → 답변 초안 → 사람 승인 → 기록/후속 액션`의 흐름을 만드는 것이다.

이 사례는 하비가 요청의 성격을 판단하고, 방울이가 관련 문서와 과거 답변을 찾고, 뽀동이가 고객에게 보낼 문장을 다듬고, 봉구가 승인된 답변이나 기록 작업을 이어받는 방식으로 보면 된다.

## 시작 상황

고객 문의는 보통 짧고 맥락이 부족하다. “이거 안 돼요”, “지난번 기능 언제 되나요?”, “가격은 어떻게 되나요?”처럼 들어온다. AI가 바로 답하면 빠르지만, 사실 확인과 약속 범위를 놓칠 수 있다.

| 문의 유형 | AI가 먼저 할 일 | 사람 승인 지점 |
|---|---|---|
| 기능 오류 | 증상 요약, 필요한 추가 정보 질문 초안 | 원인 단정 전 |
| 기능 요청 | 요구사항 초안, 제품 백로그 후보 정리 | 일정/확정 표현 전 |
| 가격/계약 | 질문 분류, 담당자 연결 초안 | 금액/조건 안내 전 |
| 사용법 질문 | 문서 링크 확인, 답변 초안 | 공개 문서가 오래됐을 때 |

## 맡긴 역할

| 역할 | 담당 |
|---|---|
| 하비 | 답변 가능/보류/담당자 연결을 판단한다 |
| 방울이 | 관련 문서, 과거 답변, 제품 상태를 확인한다 |
| 뽀동이 | 고객에게 보낼 문장을 명확하고 부드럽게 다듬는다 |
| 비벙이 | 기능 요청이면 요구사항 후보로 정리한다 |
| 봉구 | 승인된 답변 기록, 이슈 생성, 문서 링크 갱신을 실행한다 |

## 막힌 지점

Slack 응대 자동화가 실패하는 이유는 답변을 너무 빨리 보내기 때문이다. 고객에게는 “검토 중”과 “확정”의 차이가 크다. AI가 그럴듯한 문장으로 확정처럼 말하면 이후 신뢰 문제가 생긴다.

## 운영 규칙

Slack 고객응대는 아래 기준을 둔다.

1. 고객에게 직접 나가는 답변은 초안까지만 만든다.
2. 일정, 가격, 장애 원인, 계약 조건은 사람 승인 없이는 확정하지 않는다.
3. 추가 정보가 필요한 경우 질문 초안을 먼저 만든다.
4. 반복 문의는 FAQ나 WikiDocs 개선 후보로 남긴다.
5. 기능 요청은 비벙이 요구사항 정리로 넘긴다.
6. 처리 결과는 Slack에만 두지 않고 원본 위치에 기록한다.

## 따라 하는 방법

```text
하비야, 이 Slack 고객 문의를 처리할 초안을 만들어줘.

처리 기준:
1. 문의 유형 분류
2. 고객에게 바로 확인해야 할 추가 질문
3. 답변 초안
4. 사람이 승인해야 할 표현
5. 관련 문서 링크 후보
6. 기능 요청이면 비벙이가 요구사항으로 정리할 항목
7. 처리 후 기록할 위치

주의:
일정/가격/장애 원인은 확정하지 말고 확인 필요로 표시해줘.
```

## 좋은 예와 나쁜 예

| 구분 | 예시 |
|---|---|
| 나쁜 예 | “고객에게 알아서 답장해줘” |
| 좋은 예 | “답변 초안을 만들되 일정/가격/원인 단정은 확인 필요로 표시하고, 승인 후 보낼 문장으로 정리해줘” |

## 체크리스트

- 고객에게 바로 나가는 자동 발송을 막았는가?
- 확정하면 안 되는 표현을 표시했는가?
- 관련 문서나 근거 링크를 확인했는가?
- 반복 문의를 FAQ/WikiDocs 개선 후보로 남겼는가?
- 기능 요청을 제품 요구사항 흐름으로 넘겼는가?

## 확장 아이디어

Slack 고객응대 흐름이 안정되면 FAQ 자동 보강, 고객 요청 통계, 제품 백로그 후보 정리, 릴리즈 노트 작성으로 확장할 수 있다. 중요한 것은 응대 속도만 높이는 것이 아니라 고객 약속의 품질과 기록의 일관성을 함께 지키는 것이다.
