## Hermes Agent 운영 질문은 어떻게 분류할까

Hermes Agent 운영 질문은 대부분 새로운 문제가 아니라 이미 있는 혼선의 변형이다. 같은 하비인데 기억이 다르게 느껴지는 문제, profile이 다른 문제, 도구가 파일을 못 읽는 문제, gateway가 살아 있는지 헷갈리는 문제는 모두 다른 층에서 생긴다.

그래서 FAQ를 만들 때는 답변을 많이 모으는 것보다 질문을 분류하는 기준이 먼저다. 질문을 잘 분류하면 하비가 직접 답할지, 방울이에게 조사시킬지, 뽀동이가 문서로 정리할지, 봉구가 실행 검증을 맡을지 판단하기 쉬워진다.

## FAQ가 약해지는 이유

운영 FAQ가 약해지는 이유는 질문을 그대로 쌓기 때문이다.

```text
왜 기억을 못 하지?
왜 파일을 못 읽지?
왜 gateway가 켜져 있는데 답이 없지?
왜 방울이랑 뽀동이가 다르게 말하지?
```

이 질문들은 서로 달라 보이지만, 실제로는 레이어가 다를 뿐이다. 답변 모음만 있으면 새 질문이 나올 때마다 다시 설명해야 한다. 분류 기준이 있으면 새 질문도 빠르게 자리를 찾는다.

## 먼저 나눌 레이어

| 레이어 | 대표 질문 | 먼저 볼 것 |
|---|---|---|
| identity | 지금 누구에게 말하고 있나 | 하비/역할형 에이전트 호출 여부 |
| profile | 같은 이름인데 상태가 왜 다르나 | profile, config, state |
| memory | 왜 이 선호를 기억하지 못하나 | session, memory, skill 구분 |
| role | 누가 맡아야 하나 | 조사형/정리형/실행형/이미지형 역할 |
| tool | 도구가 왜 못 읽거나 못 쓰나 | 권한, 경로, MCP, API |
| runtime | 켜져 있는데 왜 안 되나 | process, gateway, cron, log |
| source of truth | 무엇을 기준으로 믿어야 하나 | GitHub repo, WikiDocs, Obsidian, shared-memory |

이 표가 있으면 FAQ가 단순 문답이 아니라 진단 흐름이 된다.

## 실제 운영 예시

로이드가 이렇게 물었다고 하자.

```text
뽀동아, 전에 말한 규칙 왜 또 빠졌어?
```

이건 바로 사과하고 끝낼 문제가 아니다. 먼저 레이어를 봐야 한다.

- 현재 session에만 있던 규칙인가?
- memory에 저장된 선호인가?
- AGENTS.md나 skill에 반영된 절차인가?
- 다른 profile이 실행 중인가?
- 압축 과정에서 세부 규칙이 약해졌나?

이렇게 보면 다음 조치가 분명해진다. 단순 수정이면 원고만 고치고, 반복 규칙이면 memory나 skill까지 고쳐야 한다.

## 운영 기준

운영 질문을 받으면 아래 순서로 분류한다.

1. 질문이 정체성, 기억, 역할, 도구, 실행, 기준 중 어디에 가까운지 본다.
2. 현재 session 문제인지 장기 규칙 문제인지 나눈다.
3. 역할형 에이전트에게 위임할 문제인지 판단한다.
4. 실행 검증이 필요한 문제면 봉구처럼 실행형 에이전트 흐름으로 넘긴다.
5. 반복될 질문이면 FAQ나 체크리스트로 남긴다.
6. 절차가 바뀌었으면 skill을 패치한다.
7. 사용자 선호가 드러났으면 memory에 남긴다.

## FAQ

### FAQ는 모든 질문을 다 모아야 하나요?

아니다. 모든 질문을 모으기보다 질문을 분류하는 기준을 만드는 것이 더 중요하다. 기준이 있으면 새 질문도 빠르게 처리할 수 있다.

### 하비가 모든 질문에 답하면 안 되나요?

하비는 메인 창구로 좋다. 다만 근거 수집은 방울이, 구조 정리는 뽀동이, 실행 검증은 봉구처럼 역할을 나누면 품질이 안정된다.

### 운영 질문이 반복되면 어떻게 해야 하나요?

반복되는 질문은 단순 답변으로 끝내지 말고 FAQ, 체크리스트, skill, AGENTS.md 중 어디에 반영할지 정해야 한다.
