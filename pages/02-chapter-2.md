## 2장. AI 개인비서 메인 창구 만들기

에르메스 에이전트(Hermes Agent)로 AI 팀을 만들 때 먼저 정해야 할 것은 에이전트 숫자가 아니라 **사용자가 어디로 말하느냐**다. 조사형, 정리형, 실행형, 이미지형 에이전트가 있어도 사용자가 매번 “이번 일은 누구에게 맡기지?”를 판단해야 한다면 자동화가 아니라 관리 업무가 하나 더 생긴다.

![2장 AI 개인비서 메인 창구 흐름](../assets/images/chapter-heroes/ch02-ai-assistant-front-door-codex.webp)

그래서 2장은 [AI 개인비서](https://wikidocs.net/345923)를 메인 창구로 세우는 문제를 다룬다. 메인 창구는 모든 일을 직접 처리하는 만능 에이전트가 아니다. 요청을 먼저 받고, 직접 할 일과 넘길 일을 나누고, 여러 결과를 다시 하나의 답으로 묶는 앞단이다.

이 책에서는 그 역할의 예시로 하비를 사용한다. 중요한 것은 이름이 아니라 구조다. 사용자는 한곳에 요청하고, 메인 창구가 뒤쪽의 [역할형 에이전트](https://wikidocs.net/345925)와 도구를 연결한다.

## 이 장에서 다루는 것

| 글 | 질문 | 핵심 |
|---|---|---|
| 02-1 | AI 개인비서 메인 창구는 왜 필요할까 | 사용자가 여러 에이전트를 직접 지휘하면 왜 피곤해지는가 |
| 02-2 | 직접 처리할 일과 역할형 에이전트에 맡길 일 | 메인 창구가 붙잡을 일과 넘길 일을 어떻게 나누는가 |
| 02-3 | 메인 창구의 강점과 병목 | 단일 창구는 왜 편하고, 어디서 막히는가 |

## 실제로 이런 장면에서 필요하다

예를 들어 “WikiDocs 책 흐름을 다시 봐줘”라는 요청은 단순 문서 리뷰처럼 보인다. 하지만 실제로는 여러 일이 섞인다.

| 섞여 있는 일 | 필요한 판단 |
|---|---|
| 기존 글이 빠짐없이 옮겨졌는지 확인 | 원본 대조 |
| 공식 기능 설명과 어긋난 부분이 없는지 확인 | 근거 확인 |
| 읽는 사람에게 필요한 흐름으로 장 순서 점검 | 구조화 |
| 본문 링크가 읽는 중 자연스럽게 이어지는지 확인 | 문서 편집/검증 |
| 기록용 문장을 읽기 쉬운 사례로 바꾸기 | 리라이트 |
| 발행 후 공개 화면에서 다시 확인 | 실행/검증 |

사용자가 이 모든 단계를 직접 나눠 지시하면 AI 팀은 도구 목록이 된다. 반대로 메인 창구가 있으면 요청은 하나로 들어오고, 안쪽에서 필요한 역할로 분해된다. 조사형은 근거를 찾고, 정리형은 책 흐름으로 바꾸고, 실행형은 검증과 발행을 맡고, 메인 창구는 전체 방향과 최종 보고를 잡는다.

## 메인 창구를 세울 때 정할 것

메인 창구를 세울 때는 세 가지를 먼저 정한다. 첫째, 사용자가 요청을 넣는 기본 입구를 하나로 둔다. 둘째, 조사/정리/실행/이미지 제작처럼 넘길 기준을 미리 둔다. 셋째, 최종 보고와 검증 책임은 다시 메인 창구가 묶는다.

## 메인 창구를 세운 뒤 확인할 것

| 남아야 할 것 | 확인 질문 | 연결되는 글 |
|---|---|---|
| 메인 창구의 역할 정의 | 사용자가 어디로 요청을 보내면 되는가 | [AI 개인비서 메인 창구](https://wikidocs.net/345892) |
| 직접 처리/위임 기준 | 하비가 바로 답할 일과 역할형 에이전트에 넘길 일을 구분했는가 | [직접 처리와 위임](https://wikidocs.net/345893) |
| 병목 신호 | 메인 창구가 느려지거나 시끄러워지는 순간을 알아볼 수 있는가 | [메인 창구의 강점과 병목](https://wikidocs.net/345894) |
| 완료 보고 기준 | 여러 역할의 결과가 하나의 답으로 통합되는가 | [Hermes 운영 시스템](https://wikidocs.net/345890) |

## 처음에 생기는 착각

역할형 에이전트를 만들면 일이 자동으로 나뉠 것처럼 보인다. 하지만 입구가 없으면 사용자가 계속 판단해야 한다.

```text
이건 먼저 조사해야 하나?
바로 문서로 정리해도 되나?
파일 수정과 검증까지 맡겨도 되나?
이미지 방향도 같이 잡아야 하나?
최종 결과는 누가 묶어야 하나?
```

이 질문을 매번 사용자가 붙잡으면 [나만의 AI 팀](https://wikidocs.net/345924)은 팀이 아니라 “봇을 관리하는 또 다른 일”이 된다. 메인 창구의 목적은 사용자가 에이전트 구조를 덜 신경 쓰고, 요청과 결과에 집중하게 만드는 것이다.

## 2장에서 세우는 기준

이 장을 읽고 나면 아래 기준이 남아야 한다.

| 기준 | 설명 |
|---|---|
| 단일 진입점 | 사용자는 먼저 누구에게 말할지 헷갈리지 않는다 |
| 직접 처리 기준 | 짧은 판단, 우선순위, 최종 보고는 메인 창구가 잡는다 |
| 위임 기준 | 조사/정리/실행/이미지처럼 깊이가 필요한 일은 역할형 에이전트로 보낸다 |
| 결과 계약 | 위임 결과는 그대로 전달하지 않고 하나의 판단으로 묶는다 |
| 보고 형식 | 사용자가 다시 묻지 않도록 완료/남음/다음이 보이게 한다 |
| 멈춤 기준 | 위험하거나 범위가 흔들리면 메인 창구가 멈추고 확인한다 |

## 읽는 순서

먼저 [AI 개인비서 메인 창구는 왜 필요할까](https://wikidocs.net/345892)에서 단일 창구가 줄여주는 부담을 본다. 그다음 [직접 처리할 일과 역할형 에이전트에 맡길 일](https://wikidocs.net/345893)에서 메인 창구가 직접 할 일과 뒤로 넘길 일을 나눈다.

마지막으로 [메인 창구의 강점과 병목](https://wikidocs.net/345894)을 읽으며 단일 창구가 언제 막히는지 확인한다. 이 기준이 잡혀야 3장의 조사형/정리형/실행형 에이전트 분리가 실제 운영 구조로 이어진다.
