## 파일은 있는데 도구는 왜 못 읽을까

파일이 눈에 보이는데 도구가 못 읽는 일은 이상해 보인다. 하지만 Hermes Agent 업무 자동화에서는 자주 생기는 문제다. 사람이 Finder, Obsidian, iCloud에서 보는 파일 위치와 에이전트 도구가 접근하는 실행 경로가 다를 수 있기 때문이다.

이 문제는 “파일이 없다”와 “파일은 있는데 도구가 접근하지 못한다”를 나눠야 풀린다. 같은 증상처럼 보여도 원인은 경로, 권한, 동기화, 실행 환경, profile 설정으로 갈린다.

## 파일이 없는 것과 못 읽는 것은 다르다

| 상황 | 의미 | 먼저 볼 것 |
|---|---|---|
| 파일이 실제로 없음 | 경로에 파일이 존재하지 않음 | 파일명, 위치, Git 상태 |
| 파일은 있는데 경로가 다름 | 사람이 보는 위치와 도구 기준 경로가 다름 | 절대경로, 현재 작업 디렉터리 |
| 동기화가 늦음 | iCloud/Obsidian 파일이 아직 내려오지 않음 | 로컬 다운로드 상태 |
| 권한이 없음 | 도구가 해당 위치를 읽을 권한이 없음 | 터미널 접근, sandbox, OS 권한 |
| profile이 다름 | 다른 에이전트 환경에서 실행 중 | config, tool, workdir |

이 구분을 하지 않으면 계속 “분명 파일 있는데?”에서 멈춘다.

## Obsidian과 iCloud에서 자주 생기는 이유

Obsidian vault나 iCloud 문서는 사람에게는 하나의 노트 폴더처럼 보인다. 하지만 자동화 도구 입장에서는 실제 로컬 경로, 동기화 상태, 공백이 포함된 경로, 접근 권한이 모두 영향을 준다.

예를 들어 HALOX Brain 같은 vault는 source of truth일 수 있지만, 도구가 읽을 때는 정확한 절대경로가 필요하다. 파일명이 비슷하거나 iCloud가 아직 다운로드하지 않은 상태라면 검색 결과가 비어 보일 수 있다.

## 실제 운영 예시

나쁜 확인은 이렇게 끝난다.

```text
파일이 있는데 왜 못 읽지?
```

좋은 확인은 원인을 나눈다.

```text
하비야, 이건 파일 존재 문제인지 도구 접근 문제인지 나눠서 봐줘.
먼저 절대경로와 현재 workdir을 확인하고,
파일이 iCloud에만 있는지 로컬에 내려와 있는지 봐줘.
필요하면 봉구가 터미널로 접근 가능 여부를 검증해줘.
```

이렇게 보면 감으로 헤매지 않고 원인을 좁힐 수 있다.

## 운영 기준

도구가 파일을 못 읽을 때는 아래 순서로 확인한다.

1. 파일의 절대경로를 확인한다.
2. 현재 workdir과 상대경로 기준을 확인한다.
3. 파일명이 정확한지 본다.
4. iCloud/Obsidian 동기화 상태를 확인한다.
5. 터미널에서 같은 경로를 읽을 수 있는지 본다.
6. profile이나 tool 권한이 다른지 확인한다.
7. source of truth가 어디인지 다시 잡는다.

## FAQ

### Finder에서 보이면 도구도 읽을 수 있는 것 아닌가요?

항상 그렇지는 않다. Finder는 사람에게 보여주는 화면이고, 도구는 실제 파일 시스템 경로와 권한을 기준으로 접근한다.

### 상대경로와 절대경로 중 무엇을 써야 하나요?

자동화와 검증 단계에서는 절대경로가 안전하다. 문서에 남길 때는 repo 기준 상대경로를 쓰되, 작업 중에는 절대경로로 원인을 확인하는 편이 좋다.
