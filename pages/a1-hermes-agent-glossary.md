## 부록 A-1. Hermes Agent 용어집

이 부록은 책을 읽다가 반복해서 만나는 용어를 빠르게 확인하기 위한 참조 페이지다. Hermes Agent는 챗봇 하나를 켜는 도구라기보다, 기억/절차/도구/채널을 나눠 실제 업무 흐름을 운영하게 만드는 AI 에이전트 프레임워크다. 용어를 외우기보다 “어떤 문제를 해결하기 위한 장치인가”로 읽으면 전체 흐름이 훨씬 덜 복잡해진다.

## 먼저 잡을 핵심 용어

| 용어 | 이 책에서의 의미 | 함께 볼 장 |
|---|---|---|
| AI 개인비서 | 사용자의 요청을 먼저 받고 흐름을 정리하는 메인 창구 | 1장, 2장 |
| 역할형 에이전트 | 조사/정리/실행처럼 실패 방식이 다른 일을 나눠 맡는 에이전트 | 3장 |
| memory | 오래 유지해야 할 사용자 선호, 기준, 안정적인 사실을 남기는 기억 | 4장 |
| session search | 과거 대화와 작업 결과를 다시 찾아 현재 요청에 이어붙이는 회상 장치 | 4장 |
| profile | 특정 에이전트의 역할, 말투, 기본 규칙을 담는 실행 기준 | 4장 |
| shared-memory | 여러 에이전트가 함께 봐야 하는 팀 공통 기준 | 4장 |
| Skill | 반복되는 절차와 검증 순서를 재사용 가능한 작업 기준으로 남기는 방식 | 6장 |
| MCP | 외부 도구와 업무 시스템을 AI 에이전트가 사용할 수 있게 연결하는 규격 | 5장 |
| gateway | Slack/Telegram/Discord/Webhook처럼 외부 채널에서 요청을 받을 수 있게 하는 입구 | 5장 |
| cron | 정해진 시간이나 주기로 AI 에이전트 작업을 시작하는 자동화 방식 | 5장, 11장 |
| toolset | 사용할 도구 묶음을 제한해 안전하고 가볍게 실행하기 위한 범위 | 5장 |
| checkpoint/rollback | 실행 전후 상태를 비교하고 문제가 생겼을 때 되돌리는 복구 기준 | 9장 |

## 헷갈리기 쉬운 구분

| 헷갈리는 조합 | 구분 기준 |
|---|---|
| memory vs session search | memory는 앞으로도 계속 필요한 기준을 남기고, session search는 과거 작업을 찾아 이어받는 데 쓴다. |
| Skill vs memory | Skill은 반복 절차와 검증 순서이고, memory는 선호나 기준 같은 안정적인 사실이다. |
| MCP vs gateway | MCP는 도구를 연결하는 방식이고, gateway는 외부 채널에서 요청을 받는 입구다. |
| cron vs Skill | cron은 언제 시작할지를 정하고, Skill은 어떻게 처리할지를 남긴다. |
| 역할형 에이전트 vs toolset | 역할형 에이전트는 맡는 일의 성격이고, toolset은 실행할 수 있는 도구 범위다. |
| GitHub 원본 vs WikiDocs 공개본 | GitHub는 수정과 검증의 source of truth이고, WikiDocs는 독자가 읽는 배포 채널이다. |

## 처음 읽을 때의 기준

처음부터 모든 용어를 외울 필요는 없다. 아래 네 가지 질문만 잡으면 된다.

1. 무엇을 기억해야 하는가?
2. 어떤 절차가 반복되는가?
3. 어떤 외부 도구와 연결해야 하는가?
4. 누가 요청을 받고 누가 실제 작업을 맡는가?

이 네 질문에 답하면 memory, Skill, MCP, gateway, cron, 역할형 에이전트가 각각 어디에 놓이는지 자연스럽게 보인다.
