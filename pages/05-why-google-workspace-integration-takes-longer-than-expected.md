## Google Workspace와 MCP 연동은 왜 오래 걸릴까

Google Workspace와 MCP 연동은 기능보다 운영 조건 때문에 오래 걸린다. Calendar, Gmail, Drive, Sheets를 AI 개인비서에 붙이는 일은 겉으로는 단순해 보이지만 실제로는 인증, 권한, 데이터 범위, 실패 알림, 실행 주기를 함께 설계해야 한다.

Hermes Agent에서 외부 도구를 붙일 때 핵심 질문은 “붙일 수 있나?”가 아니다. “누가 어떤 권한으로, 언제, 어떤 결과를 만들고, 실패하면 어디에 알려줄 것인가?”다. 이 질문에 답하지 않으면 도구는 붙어도 workflow는 오래 못 간다.

## 처음에 단순하게 보는 지점

처음에는 이렇게 생각하기 쉽다.

```text
Google Calendar 읽기만 붙이면 되겠지.
Gmail 검색만 붙이면 되겠지.
Drive 파일 찾기만 붙이면 되겠지.
```

하지만 실제 업무 자동화에서는 범위가 금방 넓어진다. 캘린더를 읽으면 시간대와 반복 일정이 따라오고, Gmail을 읽으면 개인정보와 보안 범위가 따라오고, Drive를 읽으면 파일 권한과 공유 정책이 따라온다.

## MCP는 도구 연결이지 운영 완성이 아니다

MCP는 외부 도구를 Hermes Agent에 붙이는 좋은 방식이다. 하지만 MCP 서버가 보인다고 해서 운영 준비가 끝난 것은 아니다.

| 확인할 것 | 왜 필요한가 |
|---|---|
| 인증 방식 | 토큰, OAuth, 서비스 계정 범위가 다르다 |
| 권한 범위 | 읽기만 할지, 쓰기까지 할지 정해야 한다 |
| 호출 profile | 어느 에이전트가 도구를 쓸 수 있는지 정해야 한다 |
| 실패 처리 | 오류가 조용히 묻히면 자동화가 깨진다 |
| 기록 위치 | 결과를 Slack, WikiDocs, repo, memory 중 어디에 남길지 정해야 한다 |
| 민감정보 처리 | 토큰과 개인 데이터는 문서에 원문으로 남기면 안 된다 |

그래서 MCP는 시작점이고, 운영 기준은 별도로 필요하다.

## on-demand와 자동화를 먼저 나눈다

외부 도구는 처음부터 상시 자동화로 만들 필요가 없다. 초반에는 on-demand가 더 안전한 경우가 많다.

- 가끔 확인하는 일: 하비에게 직접 요청한다.
- 반복되지만 위험이 낮은 일: skill로 절차를 남긴다.
- 정해진 시간에 필요한 일: cron으로 돌린다.
- 계속 대기해야 하는 일: gateway 상태와 autostart를 관리한다.
- 여러 도구를 엮는 일: 실패 지점과 알림 채널을 먼저 정한다.

이 순서를 무시하고 바로 자동화하면, 작은 권한 문제도 운영 장애처럼 커진다.

## 실제 운영 예시

나쁜 요청은 이렇게 시작한다.

```text
하비야, Google Workspace 다 붙여줘.
```

좋은 요청은 범위와 리스크를 나눈다.

```text
하비야, 먼저 Calendar 읽기만 on-demand로 붙일 수 있는지 봐줘.
민감정보는 저장하지 말고, 인증 범위와 실패 메시지를 정리해줘.
반복할 가치가 보이면 그때 skill이나 cron으로 넘기자.
```

이렇게 하면 도구 연결이 곧바로 운영 부채가 되는 것을 막을 수 있다.

## 운영 기준

Google Workspace나 MCP 연동을 시작할 때는 아래 순서로 본다.

1. 읽기 전용인지 쓰기까지 필요한지 정한다.
2. 개인 계정, 조직 계정, 서비스 계정 중 어떤 인증이 맞는지 본다.
3. 어떤 profile에서 도구를 쓸지 정한다.
4. on-demand, skill, cron, gateway 중 실행 형태를 고른다.
5. 실패 시 어디에 알릴지 정한다.
6. 결과를 어디에 남길지 정한다.
7. 토큰, 웹훅, 개인 데이터는 원문으로 기록하지 않는다.

## FAQ

### MCP만 붙이면 자동화가 끝나나요?

아니다. MCP는 도구를 호출할 수 있게 해주는 연결 방식이다. 운영 자동화가 되려면 실행 주기, 실패 처리, 권한 범위, 결과 기록 위치가 함께 정해져야 한다.

### 처음부터 cron으로 돌리면 안 되나요?

반복 가치와 실패 패턴을 알기 전에는 on-demand가 더 안전하다. 몇 번 직접 실행해 보고 기준이 잡히면 skill이나 cron으로 옮기는 편이 좋다.
