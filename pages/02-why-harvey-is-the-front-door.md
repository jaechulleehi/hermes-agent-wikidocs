## AI 개인비서 메인 창구는 왜 필요할까

[AI 개인비서](https://wikidocs.net/345923)에 메인 창구가 필요한 이유는 단순하다. 사용자가 여러 에이전트를 직접 고르고 지시해야 하면 AI 팀은 편해지는 것이 아니라 더 피곤해진다.

![AI 개인비서 메인 창구가 사용자 부담을 줄이는 흐름](../assets/how-image-agent-creates-wikidocs-visuals/ch2-1-ai-assistant-front-door-codex.webp)

[Hermes Agent](https://wikidocs.net/346055)를 업무에 붙이면 요청은 대부분 짧게 들어온다. “이 스레드 전체 리뷰해줘”, “WikiDocs 2장도 봐줘”, “공식 설명과 어긋난 부분 없는지 확인해줘”처럼 시작한다. 그런데 그 안에는 이전 맥락 확인, 자료 대조, 문서 리라이트, 링크 검증, 발행 후 확인까지 함께 들어 있다.

메인 창구는 이 섞인 요청을 먼저 받아 흐름으로 바꾼다. 이 책에서는 하비를 그 예시로 설명한다. 하비는 모든 일을 직접 처리하는 만능 봇이 아니라, 요청을 읽고 필요한 [역할형 에이전트](https://wikidocs.net/345925)나 도구로 넘긴 뒤 결과를 다시 하나로 묶는 AI 개인비서다.

## 멀티 에이전트가 쉽게 피곤해지는 이유

역할형 에이전트가 많아지면 처음에는 좋아 보인다. 조사형은 조사만 잘하고, 정리형은 문서만 잘하고, 실행형은 검증을 맡고, [하망이](https://wikidocs.net/345989) 같은 이미지형 에이전트는 시각 자료를 맡으면 될 것 같다.

문제는 사용자가 그 모든 역할을 직접 운영하기 시작할 때 생긴다.

```text
먼저 조사해야 하나?
바로 WikiDocs 문체로 정리해도 되나?
파일 수정과 검증까지 맡겨도 되나?
이미지까지 같이 보면 범위가 커지지 않을까?
```

이 판단을 사용자가 계속 해야 하면 AI 팀은 자동화가 아니라 관리 업무가 된다. 메인 창구는 이 부담을 줄이기 위해 존재한다.

## 실제 운영에서 메인 창구가 맡은 일

WikiDocs 책 품질 보강 작업에서 메인 창구의 역할은 “글을 쓰는 사람” 하나가 아니었다. 더 정확히는 요청을 결과로 바꾸는 앞단의 창구였다.

| 실제 상황 | 메인 창구가 한 일 | 뒤에서 필요한 역할 |
|---|---|---|
| 전체 읽는 흐름 검수 요청 | 책 전체 문제를 링크/본문/원본/공식 설명 기준으로 분해 | 구조화/검증 |
| 내부 링크가 공개 화면에서 어색한 문제 | 로컬 문서 링크와 WikiDocs 공개 링크의 차이를 확인 | 문서 편집/검증 |
| 일부 페이지가 기록용처럼 보인 문제 | 운영 기록을 읽기 쉬운 사례와 판단 기준으로 바꿈 | 리라이트 |
| 1장부터 다시 보강 | 장별 페이지를 하나의 독자 여정으로 다시 작성 | 문서화/검증/발행 |

이 흐름에서 사용자가 각 세부 작업자를 계속 지정했다면 일이 더 느려졌을 가능성이 크다. 메인 창구가 있으면 사용자는 “무엇을 얻고 싶은지”를 말하고, AI 개인비서가 “어떤 순서로 처리할지”를 잡는다.

## 메인 창구가 책임지는 것

AI 개인비서 메인 창구는 보통 여섯 가지를 책임진다.

| 책임 | 의미 | 실패하면 생기는 일 |
|---|---|---|
| 요청 해석 | 사용자가 진짜 원하는 결과를 읽는다 | 답은 했지만 필요한 결과물이 아님 |
| 범위 분해 | 한 문장 요청을 작업 흐름으로 나눈다 | 중요한 선행 확인이 빠짐 |
| 직접 처리/위임 판단 | 짧게 끝낼 일과 맡길 일을 나눈다 | 메인 창구가 병목이 되거나 위임이 과해짐 |
| 역할 배정 | 조사/정리/실행/이미지 중 어디로 보낼지 정한다 | 여러 결과가 따로 놀게 됨 |
| 중간 검수 | 조사 결과나 초안의 품질을 확인한다 | 그럴듯하지만 틀린 결과가 통과함 |
| 최종 통합 | 사용자에게 하나의 흐름으로 돌려준다 | 산출물이 조각난 채로 남음 |

## 왜 하비가 메인 창구가 되었나

하비가 메인 창구가 된 이유는 “가장 많은 일을 할 수 있어서”가 아니다. 사용자가 일을 시작하는 자연스러운 위치가 하비였기 때문이다. 대화창에서 하비를 부르면 요청 해석, 우선순위, 위임, 최종 보고가 한 흐름으로 이어진다.

메인 창구는 능력보다 위치가 중요하다. 사용자가 어디로 말해야 하는지 분명해야 하고, 그 창구가 내부 역할을 감춰줘야 한다. 그래야 사용자가 조사형/정리형/실행형/이미지형 에이전트를 매번 직접 관리하지 않아도 된다.

## 운영 기준

AI 개인비서 메인 창구를 만들 때는 아래 기준을 먼저 정한다.

- 사용자는 누구에게 먼저 말하는가?
- 메인 창구가 직접 처리할 수 있는 작업 범위는 어디까지인가?
- 조사형/정리형/실행형/이미지형 에이전트로 넘길 기준은 무엇인가?
- 중간 결과를 누가 검수하는가?
- 최종 결과는 어떤 형식으로 사용자에게 돌아오는가?
- 실패했을 때 책임 지점은 어디인가?
- 기록으로 남길 정보와 읽는 사람에게 보여줄 정보는 어떻게 나누는가?

## FAQ

### 메인 창구 하나만 있으면 다른 에이전트는 필요 없나요?

아니다. 메인 창구는 모든 일을 대신하는 존재가 아니라 일을 나누고 다시 묶는 창구다. 조사, 정리, 실행처럼 깊이가 필요한 일은 역할형 에이전트가 맡아야 한다.

### 하비가 직접 다 하면 더 빠르지 않나요?

짧은 판단은 빠를 수 있다. 하지만 근거 확인, 긴 문서 정리, 파일 수정, 이미지 제작 방향처럼 성격이 다른 일이 섞이면 직접 처리보다 위임과 통합이 더 안정적이다.

### 메인 창구가 병목이 되지 않게 하려면 어떻게 해야 하나요?

직접 처리 기준, 위임 기준, 보고 형식, 멈춤 기준을 정해야 한다. 메인 창구가 모든 일을 붙잡고 있으면 창구가 아니라 병목이 된다.
